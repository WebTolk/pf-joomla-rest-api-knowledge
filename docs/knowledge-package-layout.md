# Предлагаемая общая структура пакета знаний PF

Профиль структуры 0.1.0. Это соглашение данного дистрибутива, совместимое с
проверенным нативным контрактом PF 1.2.0. Оно не вводит новый тип инсталлера.

```text
<package-id>/
  README.md
  package.yaml
  LICENSE
  NOTICE.md
  indexes/resource-index.yaml
  resources/                    # если пакет владеет файлами
```

| Элемент | Назначение |
|---|---|
| README.md | Единая инструкция для человека и агента: предмет, версия, состав, чтение, установка, зависимости, обновление, ограничения и лицензия. |
| package.yaml | Авторитетная машинная идентичность, ресурсы, зависимости и update_sites в нативном формате PF. |
| indexes/resource-index.yaml | Генерируемый PF индекс; проверяется после изменения манифеста и при адаптации корней. |
| resources/ | Собственные обновляемые знания. Все принадлежащие пакету файлы входят в его ZIP. |
| LICENSE / NOTICE.md | Условия использования, происхождение, права сторонних авторов. |

README исходного корпуса сохраняется. Если документация поставщика лежит
в `resources/vendor/...`, её README остаётся внутри этой папки; инструкция
самого PF-пакета находится на уровне `package.yaml`. Формальные поля не следует
извлекать из произвольного текста README вместо манифеста.

## Обязательные сведения README

1. Это пакет знаний PF, его предмет и границы применимости.
2. ID и версия пакета; отдельно — версии описываемого продукта/данных.
3. Список resource IDs, зависимости и порядок чтения.
4. Предлагаемое логическое размещение и право установщика выбрать физические пути.
5. Источники, лицензия, актуальность и способ проверки результата.
6. Сервер обновлений, канал, порядок установки/rollback и локальные ограничения.
7. Какие данные относятся к профилю сайта/организации и не входят в общий пакет.

## Владение и пути

Публикуемые `path_ref` используют зарегистрированные корни и относительные пути.
Абсолютные пути компьютера автора, его `.pf`, runtime, токены, приватные реестры
и capsule/session IDs в дистрибутив не входят.

Простой пакет может владеть всеми своими `resources/`. Если несколько пакетов
используют большой общий корпус, один пакет владеет им, остальные объявляют
зависимость и ссылаются на его файлы. Каждый файл имеет одного владельца обновления.
Так выполнен этот комплект Joomla: данные принадлежат documentation, common и
компоненты являются представлениями ресурсов.

Внешние сторонние зеркала также можно описывать через knowledge_roots. Их
обновление требует отдельного поддерживаемого субъекта/процесса. Обновление
метаданных пакета само по себе не доставляет файлы во внешний каталог.

## Публикация и версии

Для каждого обновляемого пакета — собственный нативный subject типа
`knowledge_package`, semver версии пакета, ZIP с `package.yaml` в корне,
SHA-256 и `update_sites`. Сервер может объединять несколько subjects в одном
нормализованном манифесте. Общий ZIP комплекта служит для распространения,
а не выдаётся за ZIP одного native subject.

Версия знаний меняется независимо от версии PF и Joomla. Исправление знаний —
новый patch-выпуск, добавление совместимого покрытия — minor, несовместимая
структура/семантика требует major и плана миграции. Предыдущие опубликованные
артефакты не подменяются. Поддерживаемые старые версии продукта сохраняют
свои точные resource IDs.

Корень и install_path определяются принимающей стороной. Сервер не должен
навязывать install_path: в проверенном PF он имеет приоритет над локальным
путём установленного субъекта. После обновления выполняются native doctors,
проверка зависимостей и штатное обновление контекста.
