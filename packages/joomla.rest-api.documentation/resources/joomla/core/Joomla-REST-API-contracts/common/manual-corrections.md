## Создание записей

`required` XML-формы недостаточно для рабочего POST. API не применяет все defaults
формы; некоторые `TEXT NOT NULL` колонки не имеют значения по умолчанию в БД.
В таблице перечислены поля, добавленные в обязательные поля POST по проверкам
авторов Manual на чистой Joomla 6.2.0. PATCH имеет отдельную схему.

| Создаваемая запись | Дополнительно обязательные поля |
|---|---|
| Статья | `language` |
| Тег | `parent_id`, `description`, `language` |
| Поле, все шесть контекстов | `context`, `description`, `params` |
| Группа полей, все шесть контекстов | `context`, `description` |
| Модуль site/administrator | `language`, `params`; для administrator ещё `client_id: 1` |
| Меню administrator | `client_id: 1` |
| Пункт меню site | `alias`, `link` |
| Клиент баннеров | `extrainfo` |
| Контакт | `language` |
| Лента новостей | `description`, `images`, `metadata`, `metadesc`, `params` |
| Стиль шаблона site/administrator | `params` |
| Пользователь | `groups` |
| Группа пользователей | `parent_id` |

Пустая строка допустима для указанных текстовых описаний. Для `params` нужен
объект хотя бы с одним подходящим ключом: пустой объект не сохраняется.
`required` в исходной OpenAPI проверяет наличие ключа, а не эту особенность
сохранения. Использовать исправленные примеры и схему параметров выбранного
расширения. Для нового пользователя нужна хотя бы одна допустимая группа.
У нового верхнеуровневого тега `parent_id: 1` обозначает корень;
иерархию существующего сайта надо проверять отдельно.

Маршрут fields выбирает контекст чтения, но не подставляет его в новую запись.
Передавать `context` из `x-route-defaults` конкретной операции, например
`com_content.article`. Без него запись может сохраниться без контекста, а POST
вернёт 404. Имя поля должно быть уникально среди всех контекстов.

Маршруты site/administrator задают клиента для чтения. При создании модуля
administrator без `client_id: 1` может сохраниться модуль сайта с ответом 404;
при создании меню administrator — меню сайта с ответом 200. Код HTTP не заменяет
проверку сохранённого клиента/контекста. После неудачного POST сначала выяснить,
не создана ли запись, и только затем решать вопрос повтора.

## Авторизация

При включённых `API Authentication - Web Services Joomla Token` и
`User - Joomla API Token` один и тот же токен принимается как
`Authorization: Bearer <token>` и как `X-Joomla-Token: <token>`.
Плагин сначала извлекает Bearer; если извлечённый токен пуст, читает
`X-Joomla-Token`. Непустой, но неверный Bearer имеет приоритет и не вызывает
повторную попытку с `X-Joomla-Token`. Для обычного запроса выбирать один способ.
Basic зависит от отдельного включённого API-плагина. Автообновление имеет
собственную схему `X-JUpdate-Token`; её не дублируют параметром заголовка.

## Media

В URL-пути сохранять `/` между сегментами. При стандартном Apache
`AllowEncodedSlashes Off` закодированный `%2F` даёт 404 веб-сервера до Joomla.
Кодировать отдельные имена сегментов; не кодировать весь путь вместе с `/`.
Альтернатива для чтения — query-параметр `path` у `GET /v1/media/files`,
где закодированные слеши допустимы. Без `path` этот список пуст.
ID адаптера предварительно получать из `/v1/media/adapters`.

В OpenAPI `GET /v1/media/files/{path}` описывает и файл, и список каталога:
для каталога значение `path` заканчивается `/`. Ответ 200 содержит `oneOf`
для объекта и коллекции. Отдельная шаблонная операция `{path}/` убрана.
Таким образом, OpenAPI содержит 235 операций, исходная регистрация Joomla —
236 маршрутов; исходный `routes.json` и результаты его аудита сохранены.
Размер каталога `attributes.size` у локального адаптера может быть `""`.

## Ответы и примеры

Перенесены исправления схем ответов по наблюдениям авторов Manual: в том числе
`id` внутри `attributes`, структуры конфигурации и типов модулей, свободные
параметры пунктов меню и числовое `assigned` в списке стилей шаблона.
У contenthistory параметр `id` для DELETE/keep обозначает ID версии;
для списка истории — ID записи владельца. Пример ошибки PATCH users/levels
использует массив `errors`.

Исправленные request examples присутствуют и в OpenAPI, и в `examples.json`.
В `examples.json` указан источник; `upstream-captured` обозначает ответ,
снятый авторами Manual, `upstream-example` — другой пример из этого снимка.
Старые архивные примеры остаются синтетическими. Проверка этого выпуска —
валидация OpenAPI, JSON Schema, примеров и упаковки, а не новый live-сеанс Joomla.
Для операций на конкретном сайте по-прежнему нужны реальные ID, ACL, плагины,
настройки адаптеров и независимое чтение после записи.

Материалы Joomla Manual и производные дополнения распространяются по JEDL 1.0;
лицензия и атрибуция включены в пакет. Старые отчёты `validation.json` описывают
исходный статический аудит; проверка этого обновления записана отдельно.
