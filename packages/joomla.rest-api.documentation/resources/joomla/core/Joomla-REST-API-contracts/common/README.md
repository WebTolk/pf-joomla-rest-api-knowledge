# Общие правила REST API Joomla

Основная версия документации: Joomla 6.2.0. Для нового задания выбирать контракт
6.2.0. Снимки 5.4.8 и 6.1.3 сохранены как архивные версионные контракты.
Примеры синтетические: они не являются записью реального API-сеанса.

## Запросы и ответы

База /api/index.php; пути OpenAPI начинаются с /v1.
Accept: application/vnd.api+json. JSON-запись: Content-Type: application/json.
Обычный CRUD принимает ПЛОСКИЙ JSON {поле: значение}; ApiController также читает
data={поле: значение}. JSON:API data.attributes не является общей схемой записи.
Медиа, конфигурация и обновление используют собственные плоские JSON-тела.
Не преобразовывать автоматически ответ JSON:API в тело запроса.

Стандартный CRUD после POST/PATCH возвращает представление ресурса и HTTP 200:
ApiController не устанавливает 201. DELETE устанавливает 204 без обязательного тела.
Действия без setData могут возвращать 200 с пустым JSON-массивом [].
Точные форматы указаны в responses каждой операции. code внутри ошибки не обязан
совпадать с HTTP-статусом. Синтетические ответы описывают форму данных, а не
подтверждают успешное выполнение действия на сайте.

Ошибки общего слоя перечислены в responses как возможные форматы, а не обещание
каждого кода при любой невалидной записи. DELETE через ApiController может вернуть
404/409 с legacy application/json: {success,message,messages,data:{status,code,message}}.
TypeError идёт по ветке Throwable: HTTP 500, errors — объект, а не массив.
Обычный RuntimeException с code=400/410 сам по себе не задаёт HTTP: fallback
преобразует его в 500. Конкретные форматтеры Save/SendEmail/CheckinCheckout
имеют собственные правила; проверенные примеры находятся в error-formatters-6.2.0.json.

## Авторизация

Для непубличных маршрутов — X-Joomla-Token при включённых API authentication token
и user token плагинах. Basic Auth применим лишь при настроенном соответствующем
плагине. Bearer не объявляется универсальной заменой X-Joomla-Token.
У пользователя должны быть core.login.api и необходимые права компонента/записи.
Автообновление использует отдельный X-JUpdate-Token. public=true на этих маршрутах
означает пропуск обычной API-аутентификации, но не отсутствие проверки update token.
Реальные токены, пароли и персональные данные в примеры/отчёты не включать.

## Пагинация и фильтры

У стандартных списков page[offset] — целое от 0, page[limit] — размер страницы,
по умолчанию 20. Нулевой limit не означает универсальный запрос всех записей.
Это не универсальное правило: модели media возвращают весь набор; types модулей,
языковые overrides и strings/search не используют стандартное разбиение page.
Для нестандартных списков смотреть x-pagination конкретной операции.
Следовать links.next, пока следующая ссылка существует.
Использовать только перечисленные для операции filter[...] и list[...].
Универсальные sort, fields[type] и произвольные filter[...] ядром не гарантируются.
ID в JSON:API data.id — строка; числовые attributes могут зависеть от драйвера БД.

## Заполнение и PATCH

Запрос POST, запрос PATCH, list response и item response разделены.
POST проверяет обязательные поля XML-формы. PATCH догружает пропущенные колонки
таблицы до фильтрации/валидации. В снимках 5.4.8/6.1.3 повторная обработка
пропущенной даты может менять значение. В 6.2.0 ApiController восстанавливает
сохранённое UTC-значение пропущенных полей с фильтром SERVER_UTC/USER_UTC после
валидации. Явно переданная дата всё ещё проходит фильтр. Пропуск ключа, null,
пустая строка, [] и {} не взаимозаменяемы.
Не предполагать рекурсивное merge вложенных объектов. Сохранять полный затронутый
объект либо применять семантику, явно указанную для endpoint.
Формы могут принимать числовые строки "0"/"1" наряду с 0/1. Эти варианты
описаны явно; boolean допустим только при boolean-фильтре. Статические option
у динамического списка не образуют его полный enum: пункты меню, группы,
языки и ID расширяются данными сайта.
additionalProperties=false у запроса — закрытый профиль стандартной формы.
Точный requestBody имеет приоритет над XML-инвентарём UI. В частности, params
плагина существует в форме админки, но запрещён PluginsController в PATCH.
Read-only и вычисляемые поля ответа не следует копировать в PATCH.
Enum из XML — статические варианты; категории, пользователи, языки, позиции,
адаптеры и записи сторонних расширений образуют наборы данных инстанса.

## Календарь

Поле без времени принимает YYYY-MM-DD. CalendarField со временем использует
эффективный DATE_FORMAT_FILTER_DATETIME, обычно YYYY-MM-DD HH:mm:ss.
USER_UTC принимает локальное время пользователя API или сайта. ISO T/Z
автоматически допустимым не считается. У явно RFC3339-фильтров пользователей
другой контракт: там нужен date-time.
Учитывать историческое смещение зоны на дату события. После записи сверять
сохранённый UTC-момент; календарный день проверять отдельно.

## Расширяемые параметры

Пакеты содержат схемы стандартных XML-форм и параметров поставляемых ядром
модулей, плагинов, шаблонов и типов полей. Вариант выбирается по module/client_id,
folder/element, template или типу поля, указанному в задании/профиле сайта.
События preprocessForm, prepareData, onApiGetFields, onGetApiAttributes могут
расширять схему. Для стороннего расширения подключается его пакет и профиль.
Статический пакет ядра не может перечислить будущие поля стороннего плагина.
JsonValue обозначает явную точку расширения, а не подтверждённую конечную схему
сторонних данных. Указанные в coverage типы, выведенные из формы/SQL, отмечены
отдельно от явных преобразований контроллера/представления.

## Повторы и проверка

После записи выполнять независимый GET известного ID/пути и сравнивать изменённые
поля. 200 не подтверждает верность текста, дат, параметров или публичного вывода.
При 400/500/обрыве сначала читать результат: запись могла сохраниться частично.
POST не повторять вслепую. Ядро не обещает универсальные Idempotency-Key и ETag.
Перед PATCH сверять modified/version и изменяемые данные с исходным снимком.

## Браузерный fallback

Зафиксировать конкретную неподдерживаемую операцию/поле, причину и границы изменения.
Открыть правильный компонент, client/context, язык и запись; сверить поля по
name/label, типу и showon. Заполнить штатную форму, сохранить, заново открыть
и сравнить значения. Если GET доступен, выполнить и независимую API-проверку.
Для публичных изменений отдельно проверить канонический URL и видимость.
Уведомление об успешном сохранении не заменяет чтение результата.
403 не разрешает менять ACL. Проектное REST-only ограничение имеет приоритет.
UI-селекторы и локализованные подписи выбираются по фактической форме, не выдумываются.

## Границы применимости

Пакет позволяет не выяснять пробными HTTP-запросами стандартные названия и типы
полей. ID, ACL, включённые плагины, язык API, часовой пояс, адаптеры и сторонние
расширения — данные сайта. Их задаёт профиль инстанса или разрешённое чтение.
Они не могут достоверно присутствовать в общем пакете для всех сайтов.
Проверка сохранения после операции обязательна и не является запросом для
выяснения схемы. Совместимость с иной версией Joomla нужно проверять отдельно.
